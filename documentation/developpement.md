# Développement

Règle de base : le TDD. Chaque comportement nouveau commence par un test qui échoue, puis le minimum de code qui le fait passer, puis le rangement.

Le test décrit le geste visible : une commande, une erreur, une annulation. Il ne décrit pas la structure interne des domaines.

Le socle du sprint 03 a ses tests dans `packages/api-parametrique`. Ils ont été écrits avec le code. À partir de maintenant, un changement de ce paquet part d’un test rouge.
